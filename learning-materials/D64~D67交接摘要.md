## 三、D64–D70 交付能力

### D64 概念
- MCP 三角色：Host / Client / Server
- 三类原语：Tools（模型驱动）/ Resources（应用驱动）/ Prompts（用户驱动）
- 三种传输：STDIO / SSE（已废弃）/ **Streamable HTTP（生产选用）**

### D65 MCP Server（agent-mcp-server）
- 依赖：`spring-ai-starter-mcp-server-webmvc` + **`spring-ai-mcp-annotations`**
  （★ 第二个依赖不被 starter 传递引入，必须显式声明）
- 注解包路径：**`org.springaicommunity.mcp.annotation`**（不是 `org.springframework.ai.mcp.annotation`）
- 三个能力：
    - `@McpTool`：CalculatorMcpTools / OrderMcpTools
    - `@McpResource`：RagDocumentMcpResource（`rag://doc/{docId}`）
    - `@McpPrompt`：RagMcpPrompts（参数注解是 `@McpArg`，不是 `@McpPromptParam`）
- 端口：**8086**（TEI 占用 8081，已改）
- 传输：`protocol: STREAMABLE`

### D66 MCP Client（agent-core）
- 依赖：`spring-ai-starter-mcp-client`
- 配置：`agent-api/src/main/resources/config/app-mcp-client.yml`
- 自动装配 `ToolCallbackProvider`，从 Server 拉取 MCP 工具
- 工具名加前缀 `mcp_` 与本地区分：`mcp_calculate` / `mcp_getOrderStatus`

### D67 工具注册中心（agent-tool-registry）
- 包路径：`org.example.toolregistry`（不用 `org.example.registry`，避免未来冲突）
- 核心类：
    - `ToolRegistry`（接口）
    - `ToolDescriptor`（record：name / description / source / sourceId / category /
      readOnlyHint / destructiveHint / idempotentHint / openWorldHint /
      requiredRoles / callback / registeredAt / registeredBy）
    - `ToolSource`（枚举：LOCAL / MCP）
    - `InMemoryToolRegistry`（ConcurrentHashMap 实现）
- **一致性校验**：`ToolRegistrationBootstrap.validateMcpConsistency()`
  ——检测"名字含 calculate 但 schema 缺 a/b/operation"这类 bug

### D68 动态发现
- `ToolRefreshService`（agent-core）：清空 → 重扫 → 通知 listener
- `ToolRefreshListener`（接口，ToolRegistry 模块）：观察者模式
- `ToolRefreshResult`（独立 record，**静态工厂用 ok/skip/fail 而非 success/skipped/failed**
  ——避免与 record 的 accessor 同名冲突）
- 两个触发入口：
    - HTTP：`POST /fap/mcp/tools/refresh`（`ToolRefreshController`）
    - 定时：`McpToolsRefreshScheduler`（默认 5 分钟）
- **ChatService 三个工具重建入口**：
    - `@PostConstruct initToolCallbacks()`（保底，可能为空）
    - `@EventListener(ApplicationReadyEvent) @Order(100) onApplicationReady()`
    - `@Override onToolsRefreshed()`（刷新时）

### D69 RBAC（agent-core/rbac）
- **三轮演进**：
    1. 工具级：用户密级 ≥ 工具要求密级
    2. 参数级：数据归属校验（订单归属租户）
    3. 审计日志：越权写 AUDIT 独立文件
- 核心类：
    - `ToolAuthorizer`（接口，两层：authorizeTool / authorizeParams）
    - `RbacToolAuthorizer`（impl，**不加 @Component**，由 RbacBeanConfig 装配）
    - `ParamOwnershipValidator`（订单归属校验）
    - `AuthzToolCallback`（装饰器，**在 SafeToolCallback 外层**）
    - `ToolAuthorization`（record：allowed / reason）
    - `RbacProperties`（@RefreshScope 支持热加载）
    - `RbacBeanConfig`
- 包装链：`ChatClient → AuthzToolCallback（鉴权）→ SafeToolCallback（重试/超时/日志）→ 工具`
- **鉴权失败不抛异常**——返回友好文本给 LLM
- 审计：`AuditLogger.authzDeny(scope, toolName, fullUserId, reason)`

### D70 启动自检（agent-api）
- `ToolChainSelfCheck`（`@Order(200)`，晚于 Bootstrap 50 和 ChatService 100）
- 打印 4 段报告：
    1. 工具注册总览（总数 / 本地 / MCP / 分类分布）
    2. 工具画像过滤结果（每个 profile 的工具数 + 消费方映射）
    3. RBAC 配置覆盖率
    4. 关键工具可用性

## 四、D69 前置：ToolProfile（工具画像）

- 位置：`agent-core/.../core/toolprofile/`
- 核心类：
    - `ToolProfile`（模型：includeCategories / includeTools / includeSources /
      excludeTools / minSecurityLevel）
    - `ToolProfileProperties`（yml 前缀 `app.tools`，@RefreshScope）
    - `ToolProfileResolver`（解析器：resolve / resolveForConsumer / resolveNamesForConsumer）
- yml：`agent-api/src/main/resources/config/app-tool-profiles.yml`
- 四个 profile：
    - `chat-default`（ReAct 对话，排除 riskyOperation / saveLongTermMemory）
    - `plan-execute`（Plan 白名单分类）
    - `admin-console`（MCP 工具 + 高密级）
    - `audit-readonly`（只读审计）
- 消费方映射：
    - `chat-service` → `chat-default`
    - `planner-service` → `plan-execute`
    - `step-executor` → `plan-execute`
    - `plan-validator` → `plan-execute`

## 五、关键设计决策（Why）

| 决策 | 理由 |
|---|---|
| **Streamable HTTP 而非 STDIO/SSE** | 官方远程标准，兼容 Nginx/K8s，Spring AI 一等公民支持 |
| **工具注册中心独立模块** | 边界清晰，未来 agent-mcp-server 可复用，可单测 |
| **Bootstrap 放 agent-core 不放注册中心** | 需要引用具体工具类，属"业务编排" |
| **ToolRegistry 只存元数据不存发现逻辑** | 发现方式易变（本地扫/MCP 拉/未来 DB），分离后易扩展 |
| **AuthzToolCallback 在 SafeToolCallback 外层** | 鉴权失败不该重试、不该消耗超时预算 |
| **工具级 + 参数级 RBAC，暂不做数据级** | 前两层覆盖 90% 安全需求，数据级成本高 |
| **订单号用纯数字而非字母前缀** | LLM 会把 `B-1001` 规范化成 `1001` 或反之——格式不该承载语义 |
| **config 热加载用 @RefreshScope** | 生产可用，不引入 Spring Cloud Config 复杂度 |
| **语义缓存按 ID 跳过** | "查订单 1001" 和 "查订单 2001" embedding 相似度 >0.95，误命中 |

## 六、踩过的坑（重要！）

### 坑 1：`spring-ai-mcp-annotations` 不被 starter 传递
- `spring-ai-starter-mcp-server-webmvc` 不含注解模块
- 需显式加 `spring-ai-mcp-annotations`
- 注解包路径是 `org.springaicommunity.mcp.annotation`（不是 springframework）

### 坑 2：MCP Server 报 "OpenAI API key must be set"
- 根因：`agent-tools` 引了 `spring-ai-starter-model-openai`（过重）
- 修复：改成 `spring-ai-model`（只需 @Tool 注解）
- 影响：所有依赖 agent-tools 的模块不再被迫配 OpenAI Key

### 坑 3：SSE warning "SimpleAsyncTaskExecutor"
- 根因：Spring MVC 异步请求 fallback 到非池化线程
- 修复：`WebMvcAsyncConfig` 配 `sseTaskExecutor`（core=20, max=100, queue=200）

### 坑 4：record 静态工厂与 accessor 同名冲突
- `ToolRefreshResult` 里 `success()` / `skipped()` / `error()` 与字段 accessor 同名
- Java 语言禁止
- 修复：静态工厂改名 `ok()` / `skip()` / `fail()`

### 坑 5：`@RefreshScope` 导错包
- 错误：`org.springframework.cloud.context.scope.refresh.RefreshScope`（class）
- 正确：`org.springframework.cloud.context.config.annotation.RefreshScope`（annotation）

### 坑 6：`ScheduledConfig` 的配置 key 写错
- 原写 `app.rag.scan-interval-ms`，实际应为 `app.rag.ingest.scan-interval-ms`
- 导致定时任务一直用默认值 60000ms

### 坑 7：`@EventListener` 导错包
- 错误：`java.util.EventListener`（接口）
- 正确：`org.springframework.context.event.EventListener`（注解）

### 坑 8：LLM 参数幻觉
- 用户传 `B-1001`，LLM 传 `1001`（去前缀）
- 用户传 `1001`，LLM 传 `B-1001`（加前缀）
- **无法根治**——只能用纯数字编码避免

### 坑 9：Maven 版本过低
- 系统 Maven < 3.6.3，`maven-clean-plugin:3.4.1` 拒绝执行
- 修复：IDEA 切换到 Bundled Maven 3.9.11
