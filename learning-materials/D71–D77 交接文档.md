## 五、关键设计决策

| 决策 | 理由 |
|---|---|
| ObservabilityBeanConfig 用 ObjectProvider 而非 @ConditionalOnBean(Tracer.class) | @ConditionalOnBean 依赖 Bean 加载顺序，用户 @Configuration 早于自动配置 |
| TracingAdvisor 用 HIGHEST_PRECEDENCE | 包住所有业务 Advisor，Span 时长 = 全链路耗时 |
| Tracer 用 ObjectProvider 可选注入 | tracing 依赖缺失时静默跳过 |
| RabbitTopologyConfig 用 Declarables | getBeansOfType 不展开 List 元素 |
| RabbitConsumerConfig 合并成一个 List Bean | 避免 NoUniqueBeanDefinitionException |
| ContainerLifecycleManager 实现 SmartLifecycle | List 里的容器不会被 Spring 自动启动 |
| correlationId 用 UUID | requestId+时间戳会并发碰撞 |
| Worker 侧不感知 MQ | 传输层可替换 |
| TaskDispatcher.via-mq 默认 false | 单进程走 MQ 是负担 |
| Worker 不带 SelfReflectionAdvisor | 反思放到汇总层省一倍 LLM |
| ConflictDetection 快速规则前置 | 响应数 < 2 或角色数 < 2 直接返回 noConflict |
| AggregationContext 保留 3 参构造器 | 加字段不破坏旧调用 |

## 六、踩过的坑

### 坑 1：@ConditionalOnBean(Tracer.class) 时序问题（D77）

- **现象**：ObservabilityBeanConfig 整个被跳过
- **根因**：用户 @Configuration 早于 Spring Boot 自动配置评估，Tracer 还没定义
- **修复**：去掉类级 @ConditionalOnBean，改 ObjectProvider 探测 + 返回 null

### 坑 2：Spring getBeansOfType 不展开集合（D74）

- **现象**：@Bean List<Queue> 元素未被 RabbitAdmin 声明，消费者报 Failed to declare queue
- **根因**：RabbitAdmin 通过 getBeansOfType(Queue.class) 收集，不遍历 List
- **修复**：用 Declarables 包装

### 坑 3：List<SimpleMessageListenerContainer> 不会被自动启动（D74）

- **现象**：容器创建了、autoStartup=true 设了，但没有任何消费者启动
- **根因**：Spring Lifecycle 只处理"直接实现 SmartLifecycle 的 Bean"
- **修复**：加 ContainerLifecycleManager implements SmartLifecycle

### 坑 4：两个同类型 List Bean 导致 NoUniqueBeanDefinitionException（D74）

- **现象**：ContainerLifecycleManager 注入 List<SimpleMessageListenerContainer> 冲突
- **修复**：合并成一个 allListenerContainers Bean

### 坑 5：correlationId 碰撞（D74）

- **现象**：3 个子任务并发发送时报 correlationId 冲突
- **根因**：correlationId = "mq-" + requestId + "-" + currentTimeMillis，并发时同毫秒
- **修复**：改用 UUID

### 坑 6：OpenZipkin 容器 Connection refused

- **根因**：Nginx 看的是历史日志，或 Nginx 容器里的 127.0.0.1 指向自己
- **修复**：确认 docker ps；Nginx 在容器时用 host.docker.internal

### 坑 7：Zipkin proxy_pass 末尾少了 /

- **现象**：Span 上报路径 404
- **修复**（双 location）：

```nginx
location /zipkin/api/ { proxy_pass http://127.0.0.1:9411/api/; ... }
location /zipkin/     { proxy_pass http://127.0.0.1:9411/zipkin/; ... }

```
### 坑 8：@SpringBootTest 里手工 Span 不上报
根因：测试上下文和真应用的 reporter 生命周期不同

结论：D77 的 Span 上报验证必须用"真应用 + HTTP 请求"

### 坑 9：AgentMessageConverter.toTaskMessage 依赖 withMetadata(Map) 重载
修复：给 AgentMessage.task() 加 7 参重载（带 metadata）
