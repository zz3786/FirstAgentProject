# D71-D77 生产级加固与架构审查收工总结

**项目背景**：FirstAgentProject（Spring Boot 3.5.15 + Spring AI 1.1.8）

**审查范围**：模块依赖、Advisor 链、RBAC、RAG、线程池、配置治理、可观测性
**当前状态**：全部审查项通过，系统核心隐患清零。

## 一、 核心修复与改造清单（8 项）

### 1. 可观测性 (Tracing & Log)
- **修复 MDC 跨线程丢失**：增加 `brave-context-slf4j` 依赖，注册 `ReactorMdcConfig` 并开启 `spring.reactor.context-propagation: auto`。解决 SSE/Reactor 线程中 `[traceId,spanId]` 为空的问题。
- **修复 ToolLoggingAdvisor 不执行**：将其 `getOrder()` 从 `Ordered.LOWEST_PRECEDENCE` 改为具体数字（如 `1001`），避开 Spring AI 链尾占位符冲突。
- **日志路径统一**：修改 `logback-spring.xml`，使用 `<springProperty>` 读取 `app.log.home`，通过 profile 区分本地（`./logs`）与生产（`/var/log/firstagent`），杜绝日志分裂。
- **采样率修正**：将 `dev` profile 的 `management.tracing.sampling.probability` 从 `0.1` 修正为 `1.0`。

### 2. 安全与 RBAC
- **修复参数级越权漏洞**：重构 `ParamOwnershipValidator.inferTenantFromOrderId`。修复了“非纯数字订单号（如 B10001）”被误判为公共订单放行的漏洞，现在能精准识别字母前缀（A/B）并拒绝跨租户访问。

### 3. RAG 检索链路优化
- **关键词精准召回**：修改 `KeywordSearchService`，采用“方案 B”，对中文 Query 的前 2 个 2-gram 强制加 `+` 号（MySQL 强约束）。将垃圾召回从“无限 10 条”降至“精准 1~5 条”，大幅降低 TEI 重排压力。
- **参数调优**：将 `top-k` 设为 `5`，`similarity-threshold` 设为 `0.6`，`rerank.min-score` 设为 `0.5`，融合权重采用 `0.5 / 0.5`，实测证明在 TEI 重排兜底下，召回极度稳定。

### 4. 线程池与并发治理
- **解决静态池泄露**：将 `SafeToolCallback.EXECUTOR`（原 `static final`）迁移为 `ToolExecutorConfig` 中的 Spring Bean（`toolCallbackExecutor`），由 Spring 管理生命周期，支持优雅停机（`WaitForTasksToCompleteOnShutdown`）。

### 5. 配置治理与依赖清理
- **依赖精简**：清理了 `agent-observability` 和 `agent-mcp-server` 中冗余的 `agent-common` 依赖。
- **配置解耦**：将 `spring.application.name` 迁至 `application.yml`；将 `spring.rabbitmq` 规划至基础设施层；通过 `spring.config.activate.on-profile` 实现多环境隔离。

## 四、 下一步演进建议（可选）

1. **RAG 评估集扩充**：当前 `eval-queries.json` 中的问题过于字面化，建议补充 20% 的口语化、同义词 Query，以真实体现向量检索的价值。
2. **Zipkin 持久化**：目前 Zipkin 为内存存储，重启丢失，生产部署时建议接入 MySQL 或 Elasticsearch。
3. **前端 TraceId 透传**：在 `GlobalExceptionHandler` 或 Filter 中提取 `X-Trace-Id` 返回给前端，方便前端报错时一键截图排查。
