# D46 · 元数据过滤设计文档

> 使用 VectorStore 的过滤表达式，按时间、部门等标签精准过滤
>
> 目标：让"相似但无关"的 chunk 进不了候选集，同时避免跨租户/跨部门的越权检索。

---

## 一、背景与目标

### 1.1 现状问题

`HybridSearchService.search(query)` 目前是**全局检索**——任何查询都会在所有文档的所有 chunk 里找最相似的。带来两类问题：

| 问题 | 表现 | 后果 |
|---|---|---|
| **越权检索** | 用户 A 的私有文档被用户 B 召回 | 数据泄露 |
| **噪声污染** | "2024财务制度"和"2025财务制度"同时召回 | 模型看到矛盾信息后胡编 |
| **精确性差** | 用户问"研发部报销标准"，财务部条款也被召回 | Top-K 被无关内容占据 |

### 1.2 设计目标

> **在向量检索阶段就用结构化条件做预过滤，让不满足条件的 chunk 根本进不了候选集。**

关键点：**过滤发生在检索时，不是检索后**。Qdrant 在 HNSW 图遍历时就能跳过不匹配点，比"召回 Top-K 再丢弃"高效得多。

## 二、核心设计思想

### 2.1 三层职责分离

```
┌─────────────────────────────────────────────────────┐
│  写入侧（Ingest）                                    │
│  ─────────────────                                   │
│  injectMetadata()  →  把业务维度（department/year）  │
│                        写入 Document.metadata        │
│                        ↓                             │
│  Qdrant: payload   +   MySQL: 表列                   │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│  传输侧（Filter 模型）                               │
│  ─────────────────                                   │
│  RagFilter record  →  中立的过滤条件表达             │
│                        ↓                             │
│  同时翻译成：                                        │
│    - Filter.Expression（给 Qdrant）                  │
│    - SQL WHERE 参数（给 MySQL）                      │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│  检索侧（Search）                                    │
│  ─────────────────                                   │
│  向量检索（Qdrant Payload Index 过滤）               │
│  + 关键词检索（MySQL B-Tree 过滤）                   │
│  → 融合 → TEI 重排                                   │
└─────────────────────────────────────────────────────┘
```

### 2.2 三个关键决策

**决策 1：过滤维度用 `record` 显式声明，不用 `Map`**

```java
// ❌ Map 方式：丢失类型信息，调用方不知道传什么
Map<String, Object> filter = Map.of("dept", "财务部", "year", 2024);

// ✅ record 方式：类型安全、IDE 可补全、契约显式
RagFilter filter = new RagFilter(
    List.of("财务部"),   // departments
    2024,                // yearFrom
    null,                // yearTo
    null,                // docTypes
    null                 // sources
);
```

**决策 2：过滤条件作为"可选维度"，null 表示不过滤**

每个维度都是 `Optional` 语义——调用方只传关心的维度，其余留 null。避免"必须传全部维度"的僵化契约。

**决策 3：两路检索共用同一个 `RagFilter` 对象**

向量路翻译成 `Filter.Expression`，关键词路翻译成 SQL WHERE 参数。**上层语义统一，下层实现分离**——这是"可移植过滤"的核心。

## 三、数据模型设计

### 3.1 过滤条件模型

```java
public record RagFilter(
        List<String> departments,   // 部门（IN 多值）
        Integer yearFrom,           // 年份下界（>=）
        Integer yearTo,             // 年份上界（<=）
        List<String> docTypes,      // 内容类型（IN 多值）
        List<String> sources        // 来源文件（IN 多值）
) {
    public static RagFilter empty();
    public boolean isEmpty();
    public Filter.Expression toExpression();   // 转 Qdrant 过滤表达式
}
```

### 3.2 Metadata 字段约定

| 字段 | 类型 | 来源 | 用途 |
|---|---|---|---|
| `doc_id` | String | `saveFile()` 生成 UUID | 去重键、删除定位 |
| `source` | String | 原文件名 | 展示、来源过滤 |
| `file_path` | String | 存储文件名 | 下载链接生成 |
| `chunk_index` | Integer | 生产者填 | 去重键、排序 |
| `total_chunks` | Integer | 生产者填 | 分块完整性校验 |
| **`department`** | **String** | **`injectMetadata` 推断** | **部门过滤** |
| **`year`** | **Integer** | **`injectMetadata` 推断** | **年份范围过滤** |
| **`content_type`** | **String** | **解析器填 / 兜底** | **类型过滤** |
| `sheet_name` | String | `TableExtractService` | 表格专属 |
| `row_start` / `row_end` | Integer | `TableExtractService` | 行定位 |
| `page_number` | Integer | PDF 解析器 | 页定位 |

**加粗的三个字段是本课新增的过滤维度**。

## 四、写入侧流程

### 4.1 流程图

```
文件入库
    ↓
saveFile() → docId / originalName / storedName
    ↓
解析 → List<Document>
    ↓
切片（表格路径跳过）
    ↓
★ injectMetadata(chunks, docInfo)
    ├─ putIfAbsent(doc_id, source, file_path, chunk_index, total_chunks)   ← 通用标识
    ├─ putIfAbsent(department, inferDepartment(originalName))              ← D46 新增
    ├─ putIfAbsent(year, inferYear(originalName))                          ← D46 新增
    └─ putIfAbsent(content_type, "text")                                   ← D46 新增（兜底）
    ↓
vectorStore.add(chunks) → Qdrant（payload 带过滤字段）
    ↓
saveToMysql(chunks, docInfo) → MySQL（新列同步写入）
```

### 4.2 关键实现

**改动位置**：`DocumentIngestService.injectMetadata()`

```java
private void injectMetadata(List<Document> chunks, DocInfo docInfo) {
    // 从文件名推断业务维度（生产环境建议改为入库参数）
    String department = inferDepartment(docInfo.originalName());
    Integer year = inferYear(docInfo.originalName());

    for (int i = 0; i < chunks.size(); i++) {
        Map<String, Object> meta = chunks.get(i).getMetadata();

        // 通用文档标识（D44 已有）
        meta.putIfAbsent("doc_id", docInfo.docId());
        meta.putIfAbsent("source", docInfo.originalName());
        meta.putIfAbsent("file_path", docInfo.storedName());
        meta.putIfAbsent("chunk_index", i);
        meta.putIfAbsent("total_chunks", chunks.size());

        // ★ D46：业务过滤维度
        if (department != null) meta.putIfAbsent("department", department);
        if (year != null)       meta.putIfAbsent("year", year);
        meta.putIfAbsent("content_type", "text");   // 解析器已填的不覆盖
    }
}
```

**改动位置**：`DocumentIngestService.saveToMysql()`

```java
private void saveToMysql(List<Document> chunks, DocInfo docInfo) {
    List<RagChunk> entities = new ArrayList<>();
    for (int i = 0; i < chunks.size(); i++) {
        Document chunk = chunks.get(i);
        Map<String, Object> meta = chunk.getMetadata();

        RagChunk entity = new RagChunk();
        entity.setDocId(docInfo.docId());
        entity.setChunkIndex(i);
        entity.setSource(docInfo.originalName());
        entity.setContent(chunk.getText());
        entity.setFilePath(docInfo.storedName());

        // ★ D46：同步过滤维度到 MySQL
        entity.setDepartment((String) meta.get("department"));
        entity.setContentType((String) meta.get("content_type"));

        Object yearObj = meta.get("year");
        if (yearObj instanceof Number n) {
            entity.setYear(n.intValue());
        } else if (yearObj instanceof String s && !s.isBlank()) {
            try { entity.setYear(Integer.parseInt(s)); } catch (NumberFormatException ignore) {}
        }

        entities.add(entity);
    }
    ragChunkMapper.batchInsert(entities);
}
```

### 5.1 流程图

```
用户问题 + RagFilter
    ↓
HybridSearchService.search(query, filter)
    ├──────────────────────────────────────────┐
    ↓                                          ↓
① 向量检索（带过滤）                        ② 关键词检索（带过滤）
   vectorSearch(query, topK, filter)          keywordSearchService.search(query, topK, filter)
   ├─ filter.toExpression()                   ├─ filter.departments() → SQL IN

   │    .filterExpression(expr)               ├─ filter.yearTo()      → SQL <=
   └─ Qdrant: Payload Index 加速              └─ filter.docTypes()    → SQL IN
    ↓                                          ↓
    └──────────────────────────────────────────┘
                    ↓
            ③ 融合（weighted / RRF）
                    ↓
            ④ TEI 重排
                    ↓
            ⑤ RagAdvisor 注入 Prompt
```

### 5.2 关键实现

**改动位置**：`HybridSearchService.vectorSearch()`

```java
private List<Document> vectorSearch(String query, int topK, RagFilter filter) {
    SearchRequest.Builder builder = SearchRequest.builder()
            .query(query)
            .topK(topK);

    if (ragProperties.getSimilarityThreshold() > 0) {
        builder.similarityThreshold(ragProperties.getSimilarityThreshold());
    }

    // ★ D46：施加过滤条件
    if (filter != null && !filter.isEmpty()) {
        Filter.Expression expr = filter.toExpression();
        if (expr != null) {
            builder.filterExpression(expr);
        }
    }

    return vectorStore.similaritySearch(builder.build());
}
```

**改动位置**：`KeywordSearchService.search()`

```java
public List<Document> search(String query, int topK, RagFilter filter) {
    String booleanQuery = buildBooleanQuery(query);
    List<RagChunk> chunks = ragChunkMapper.fulltextSearchWithFilter(
            booleanQuery, topK,
            filter == null ? null : filter.departments(),
            filter == null ? null : filter.yearFrom(),
            filter == null ? null : filter.yearTo(),
            filter == null ? null : filter.docTypes()
    );
    return chunks.stream().map(this::toDocument).toList();
}
```

**改动位置**：`RagAdvisor.enrich()`

```java
private ChatClientRequest enrich(ChatClientRequest request) {
```

## 六、设计要点（核心）

### 要点 1：过滤必须发生在检索阶段，而非检索后

| 方案 | 性能 | 精度 |
|---|---|---|
| **检索后过滤**（先召回 Top-K 再丢弃） | 召回浪费计算 | Top-K 被无关内容占据 |
| **检索时过滤**（Qdrant 在 HNSW 遍历时跳过） | 只召回命中点 | Top-K 全是相关的 |

**Qdrant 的 Payload Index 让检索时过滤几乎零成本**——但**必须建索引**，否则退化为全量扫描。

### 要点 2：Redis VectorStore 与 Qdrant 行为不同

| | RedisVectorStore | QdrantVectorStore |
|---|---|---|
| 过滤能力 | 必须显式声明 `metadataFields` | 开箱即用 |
| 未声明时行为 | **静默返回空结果**（最坑） | 正常过滤 |
| 字段类型 | 必须指定 TAG/TEXT/NUMERIC | 动态推断 |

**你的 `SemanticCacheService` 已经正确声明了 `tenant_id` 为 TAG**——但 RAG 主库 Qdrant 侧需要 `QdrantIndexInitializer` 建 Payload Index。

### 要点 3：过滤"无结果"时不能降级

```java
// ❌ 错误：过滤无结果 → 退化为不过滤
if (results.isEmpty()) {
    results = hybridSearchService.search(query);   // 降级
}

// ✅ 正确：无结果就返回空，让模型说"无法回答"
if (results.isEmpty()) {
    log.info("过滤后无结果，跳过注入");
    return request;   // 不注入任何资料
}
```

**降级会破坏过滤的语义**——用户按"财务部"过滤，结果返回研发部内容，等于过滤失效。

### 要点 4：过滤条件的传递用 `advisor param`，不用方法参数

```java
// ❌ 错误：Advisor 方法签名固定，无法加参数
public Flux<String> adviseStream(ChatClientRequest request, RagFilter filter, ...)

// ✅ 正确：用 context 传递
request.context().get("rag_filter")
```

`ChatClientRequest.context()` 是 Spring AI 提供的**跨 Advisor 传参通道**——和 `MessageChatMemoryAdvisor` 读 `CONVERSATION_ID` 是同一个机制。

### 要点 5：`year` 存 `Integer`，不存 `String`

```java
// ❌ 错误：存字符串
meta.put("year", "2024");   // 范围查询 "99" > "100" 的经典问题

// ✅ 正确：存整数
meta.put("year", 2024);     // Qdrant 自动识别为 Integer，支持 >= / <=
```

### 要点 6：两路检索的过滤必须一致

如果向量路过滤了，但关键词路没过滤，融合时会混入被过滤的 chunk。**两路过滤必须用同一个 `RagFilter` 对象**——这是设计的核心保障。

### 要点 7：`@Order(50)` 让索引先于入库扫描

```java
QdrantIndexInitializer  @Order(50)   →  建索引
RagStartupRunner        @Order(100)  →  扫描入库
```

**先建索引再入库**——否则入库时的过滤字段没有索引，性能差。

## 七、踩坑清单

| 坑 | 现象 | 解法 |
|---|---|---|
| Redis 未声明 metadataFields | 过滤静默返回空 | `RedisVectorStore.builder().metadataFields(TAG("tenant_id"))` |
| Qdrant 未建 Payload Index | 小数据量正常，大数据量断崖变慢 | `QdrantIndexInitializer` 启动时建 |
| metadata 未注入过滤字段 | 过滤报错或永远返回空 | `injectMetadata` 补 `department` / `year` / `content_type` |
| year 存成 String | 范围查询结果错乱 | 存 `Integer`，Qdrant 自动识别为数值型 |
| 过滤后无结果时"降级" | 用户看到不相关的结果 | **绝不降级**——无结果就返回空 |
| MySQL 侧过滤缺字段 | 向量路过滤了，关键词路没过滤 | `rag_chunks` 表加列 + Mapper 动态 SQL |
| `Filter.Expression` 与字符串混用 | 类型不安全 | 统一用 `Filter.Expression` |
| `PayloadSchemaType` 路径写错 | 编译失败 | 在 `io.qdrant.client.grpc.Collections` 包下 |
| `@Order` 影响 `@Scheduled` | 顺序错乱 | `@Order` 只对 ApplicationRunner 生效 |
| `inferDepartment` 硬编码文件名规则 | 部门字段不准确 | 生产环境改为入库参数传入 |

## 九、一句话总结

> **元数据过滤的价值不在"筛掉不相关的"，而在"让过滤成为检索的默认动作"。**
> **Spring AI 的 `Filter.Expression` 提供了跨向量库的可移植语法，但 Redis 和 Qdrant 的行为差异是最大的坑——Redis 必须显式声明 `metadataFields`，Qdrant 则要建 Payload Index。**
> **把过滤条件做成 `RagFilter` record 而非散落的 `Map`，让"合法过滤维度"成为代码里的显式契约，而不是口头约定。**
